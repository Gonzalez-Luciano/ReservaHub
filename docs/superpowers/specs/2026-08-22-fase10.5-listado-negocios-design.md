# Fase 10.5 — Listado público de negocios (diseño)

Fecha: 2026-08-22
Estado: aprobado en alcance, pendiente de plan de implementación.
Rama: `feat/phase-10.5-public-business-index`

## 1. Objetivo

Hoy un cliente solo puede llegar a un negocio si conoce el slug de antemano: la única ruta pública de
negocio es `GET /negocios/{business:slug}`. No existe ni backend ni frontend para descubrir qué
negocios hay. Esta fase cierra esa brecha con lo mínimo que la vuelve usable: un índice web, su
equivalente REST para el cliente autenticado por token, un punto de entrada desde la portada y datos
de demo con más de un negocio.

Es una fase deliberadamente chica, intercalada entre el tiempo real (Fase 10) y el rediseño
(Fase 11). **El criterio de éxito principal es que no se regresione nada**: la superficie nueva es
aditiva y no toca ningún flujo existente.

**Fuera de alcance, explícito:** paginación, búsqueda, filtros, categorías o rubros de negocio,
geolocalización, ordenamiento configurable, imágenes o logos en el listado, destacados o ranking,
SEO/sitemap, y cualquier trabajo visual — el diseño es de la Fase 11, que rediseñará también esta
página.

## 2. Punto de partida verificado

Verificado contra el código en `main` (commit `9fbf64c`) antes de escribir este documento.

- `app/Http/Controllers/Public/BusinessController.php` tiene **solo** `show()`.
- `routes/public.php` pone todas las rutas públicas de negocio bajo
  `Route::prefix('negocios/{business:slug}')->middleware(BindPublicBusiness::class)`. No hay ninguna
  ruta pública de negocio sin slug.
- `BindPublicBusiness` resuelve el negocio por slug, aborta 404 si `is_active` es falso y liga la
  instancia al contenedor (`app()->instance(Business::class, ...)`), que es lo que después lee
  `BusinessScope`.
- `App\Models\Business` **no** aplica `BusinessScope` — es la raíz del tenant. Una consulta
  `Business::where('is_active', true)` corre sin contexto de negocio y sin lanzar
  `MissingBusinessContextException`.
- `resources/js/Pages/Home.jsx` es un `<h1>` más un link condicional a `/mis-reservas` para
  clientes.
- En `routes/api.php`, el grupo del cliente es
  `Route::middleware(['auth:sanctum', BindPublicBusiness::class])->prefix('businesses/{business:slug}')->name('public.')`.
  Todas sus rutas exigen slug; no hay índice.
- `App\Http\Controllers\Api\ServiceController::index()` es el precedente de un índice del grupo
  cliente: sin Policy, filtra por `is_active`, ordena por nombre y responde
  `ApiResponse::success(ServiceResource::collection(...))` **sin paginar**.
- `App\Http\Resources\BusinessResource` expone `id`, `name`, `slug`, `timezone`, `currency`,
  `cancellation_hours`. Hoy lo usa `Api\BusinessController::show()` (staff, con Policy).
- `database/seeders/DemoSeeder.php` crea **un solo** negocio (`peluqueria-demo`) con un owner, dos
  empleados, cinco servicios y horarios de lunes a viernes. Su idempotencia es un `return` temprano:
  `if (Business::where('slug', 'peluqueria-demo')->exists()) { return; }`.
- `docs/DEPLOYMENT_HANDOFF.md` describe el contenido del seeder; queda desactualizado al cambiarlo.

## 3. Decisiones tomadas

| Decisión | Elegido | Por qué |
|---|---|---|
| Superficie | Web **y** API REST | La API de Fase 7 tiene el mismo agujero: un cliente con token tampoco puede descubrir negocios. |
| Auth de la API | `auth:sanctum` | El endpoint es para el cliente ya logueado, que tiene token. Mantiene simétrico el grupo cliente de la API, donde todas las rutas exigen token. |
| Auth de la web | Abierta a invitados | Mismo criterio que `/negocios/{slug}`: solo `/reservar` exige sesión. |
| Filtro | Solo `is_active = true` | Un único invariante, el mismo que ya aplica `BindPublicBusiness`. Un negocio activo sin servicios activos puede llegar a una página vacía: aceptado, no lo resolvemos acá. |
| Paginación | No | Escala de demo. Precedente: `Api\ServiceController::index`. |
| Datos de demo | Segundo negocio en `DemoSeeder` | Con un solo negocio el listado muestra una fila y el smoke de aislamiento entre negocios de la Fase 10 (paso 7, "staff de otro negocio") no tiene con qué correrse. |

## 4. Diseño

### 4.1 Web — `GET /negocios`

Ruta **fuera** del grupo con prefijo `negocios/{business:slug}`: ese grupo lleva
`BindPublicBusiness`, que necesita un slug. Va en `routes/public.php`, sin middleware de auth, con
nombre `public.business.index`. No hay shadowing con `negocios/{business:slug}`: son rutas de
segmento distinto y Laravel las distingue por forma, no por orden.

`Public\BusinessController::index()`:

```php
return Inertia::render('Public/Business/Index', [
    'businesses' => Business::where('is_active', true)->orderBy('name')->get(['id', 'name', 'slug']),
]);
```

Proyección explícita de columnas: el listado es público y anónimo, no expone ajustes del negocio.

`resources/js/Pages/Public/Business/Index.jsx`: `PublicLayout` + `<ul>` de links a
`/negocios/{slug}`, mismo mínimo visual que `Show.jsx` (Tailwind directo, sin librería de
componentes), más un estado vacío cuando no hay negocios activos.

### 4.2 API — `GET /api/businesses`

Ruta **fuera** del prefijo `businesses/{business:slug}` (ese lleva `BindPublicBusiness`), dentro del
bloque `auth:sanctum`. No lleva `EnsureBusinessContext`: el endpoint no consulta ningún modelo con
`BusinessScope`, así que no necesita negocio actual — y no debe tenerlo, porque el consumidor es un
cliente sin negocio propio.

Método `index()` en `App\Http\Controllers\Api\BusinessController`. Esa clase ya mezcla audiencias en
el namespace plano de `Api\` (igual que `Api\ServiceController`, que sirve al grupo cliente); `show`
y `update` siguen autorizando por Policy y `index` no lleva Policy, igual que
`Api\ServiceController::index`.

```php
$businesses = Business::where('is_active', true)->orderBy('name')->get();

return ApiResponse::success(BusinessResource::collection($businesses));
```

Reusa `BusinessResource` en vez de crear un recurso casi idéntico: ninguno de sus campos es
sensible, y `timezone`, `currency` y `cancellation_hours` le sirven al cliente que después va a
reservar. Respuesta sin paginar, con el envelope estándar `{success, data, message, errors}`.

Documentar la fila nueva en `docs/api.md`, en la tabla de endpoints del cliente.

### 4.3 Punto de entrada

`Pages/Home.jsx` gana un link "Ver negocios" a `/negocios`, visible siempre (no condicionado al rol,
porque el listado es público). Sin esto el listado solo se alcanza escribiendo la URL a mano.

### 4.4 Datos de demo

`DemoSeeder` siembra un segundo negocio con su propio owner, empleado, servicios y horarios. Esto
obliga a cambiar la forma de la idempotencia: el `return` temprano por `peluqueria-demo` haría que en
cualquier instalación ya sembrada el segundo negocio nunca aparezca. El guard pasa a ser **por
negocio** (se siembra el que falte), con el sembrado de un negocio extraído a un método privado
parametrizado.

Actualizar `docs/DEPLOYMENT_HANDOFF.md`, que hoy describe el contenido exacto del seeder.

## 5. Tests

Regresión: suite completa (`php artisan test`) y `vendor/bin/pint --test` en el worktree, más
`db:seed --class=DemoSeeder` corrido dos veces para comprobar la idempotencia.

## 6. Riesgos de regresión

| Riesgo | Mitigación |
|---|---|
| `GET /negocios` interfiere con `GET /negocios/{slug}` | Rutas de forma distinta; `tests/Feature/Public/BusinessBookingTest` ya cubre el `show` y debe seguir verde. |
| El seeder deja de ser idempotente o rompe el smoke de Fase 10 | Guard por slug de cada negocio; correr el seeder dos veces como verificación explícita. |
| Página Inertia nueva sin build | `pnpm build` antes de correr la suite en el worktree (sin `public/build`, todas las páginas Inertia fallan). |
| El índice de la API se cuela en el grupo con `BindPublicBusiness` | La ruta se declara fuera de ese prefijo; el test sin token (401) y el listado con token lo verifican. |
